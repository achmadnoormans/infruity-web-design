Dokumentasi Frontend
Handoff untuk Tim Backend - Infruity ERP

Dokumen ini berisi panduan teknis mengenai struktur frontend dari sistem ERP Infruity. Frontend saat ini menggunakan HTML, Tailwind, Alpine JS dan dibangun menggunakan data dummy yang di-generate pada sisi klien (client-side). Tugas tim backend adalah menghubungkan data dinamis dari database (API) untuk menggantikan data dummy ini.

1. Teknologi Utama

  • Struktur & Styling: HTML5 & Tailwind CSS
  • State Management & Interaksi: Alpine.js (tersemat pada tag <body x-data="...">)
  • Ikon: Phosphor Icons (versi web)

2. Arsitektur State Management (Alpine.js)

Seluruh status aplikasi (state) dikelola oleh Alpine.js di dalam tag <body>. Tim backend hanya perlu me-render atau menyuntikkan (inject) data JSON ke dalam inisialisasi x-data ini saat memuat halaman, atau mengambilnya via API (AJAX/Fetch) dan memperbarui state Alpine.

Variabel utama yang perlu diperhatikan:

  • activePage: String yang mengatur halaman apa yang sedang aktif (default: 'dashboard').
  • sidebarOpen & sidebarCollapsed: Boolean pengatur visibilitas dan mode sidebar.
  • expandedMenus: Array berisi ID parent menu yang sedang terbuka (misal: ['master', 'pengaturan']).
  • currentTheme: Index dari array themes (0 = default hijau, dll).

3. Struktur Data Dashboard (JSON Payload)

Saat ini, data grafik dan metrik dashboard dihasilkan secara otomatis oleh fungsi JavaScript generateRealisticDummyData(). Tim backend harus menghapus pemanggilan fungsi ini dan langsung melempar data asli berformat JSON.

Sistem mengharapkan array weeks (filter) dan weeklyData (data aktual) dengan struktur berikut:

weeks (Daftar Filter Minggu)

[
  "22 Jun - 28 Jun 2024",
  "29 Jun - 5 Jul 2024"
]

weeklyData (Data Agregat per Minggu)

Array ini indeksnya harus selaras/sama dengan array weeks. Jika filter minggu diubah (currentWeekIndex), maka data di dashboard akan mengambil dari indeks weeklyData yang sesuai.

Logika Tanggal Penting (Sabtu - Jumat)

1. Siklus 1 minggu dalam sistem ini didefinisikan dari Sabtu hingga Jumat (7 hari). Array *History harus berisi persis 7 angka.

2. Untuk hari-hari yang belum terjadi di masa depan dalam minggu berjalan (misal hari ini adalah hari Rabu, maka Kamis dan Jumat belum ada transaksi), Backend HARUS mengirimkan nilai 0 untuk hari-hari tersebut dalam History array (contoh: [400, 300, 200, 0, 0, 0, 0]).

Frontend sudah memiliki logika filter(v => v > 0) pada kalkulasi Math.min yang akan mengabaikan nilai 0 ini sehingga tidak merusak kalkulasi data metrik "Terendah".

4. Mekanisme Routing & Render Halaman

Frontend ini menggunakan pendekatan Single Page Application (SPA) pseudo-SPA melalui manipulasi DOM x-show milik Alpine.

Setiap halaman/modul dibungkus dalam div bersyarat seperti ini:

<div x-show="activePage === 'dashboard'" x-cloak> ... Konten Dashboard ... </div>
<div x-show="activePage === 'produk'" x-cloak> ... Konten Master Produk ... </div>

Untuk menginisialisasi rute/menu baru, Backend harus mendaftarkannya pada tiga tempat di dalam state utama Alpine:

  1. Link Navigasi Sidebar: <a href="#" @click.prevent="setPage('namaRute')">
  2. pageGroups Object: Pemetaan halaman ke parent grup, misal pageGroups: { namaRute: 'parentGroup' }. Ini penting untuk highlight parent menu dan dinamisasi breadcrumb.
  3. pageTitle Object: Pemetaan halaman ke judul teks, misal pageTitle: { namaRute: 'Judul Halaman' }.

5. Komponen Grafik (Custom Charts)

Grafik batang dan area dibangun murni dari manipulasi ukuran <div> menggunakan Tailwind dan Alpine JS, bukan library eksternal seperti Chart.js atau ApexCharts. Ini menjamin performa sangat ringan dan kustomisasi desain 100%.

  • Proporsi Tinggi Batang: Dikalkulasi berdasarkan proporsi terhadap nilai tertinggi dari array: (nilaiHarian / maxNilaiMingguItu) * 90%.
  • Sistem Tooltip Harian: Diatur oleh fungsi interaksi kursor di dalam file (handleMouseMove, formatTooltipVal).
  • Tugas Backend: Backend tidak perlu menyentuh maupun mengubah logika grafik ini. Selama payload JSON yang disuplai (*History) sesuai spesifikasi di atas, grafik akan merender dirinya sendiri dengan akurat.

6. Fitur Bel Notifikasi

Status ada atau tidaknya notifikasi dikelola melalui properti boolean hasUnread. Titik merah pada bell icon menggunakan fungsi x-show="hasUnread".

  • Ubah inisialisasi pada div pembungkus notifikasi: x-data="{ notifOpen: false, hasUnread: true }"
  • Buat hasUnread reaktif terhadap data dari API (misal unreadCount > 0).
  • Saat ini dropdown notifikasinya masih bersifat statis (hardcoded HTML). Backend dapat membungkus list item dengan <template x-for="notif in notifications"> untuk melooping data JSON notifikasi yang ditarik dari database.
